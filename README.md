# DelayedNotifier
DelayedNotifier — сервис для отложенных уведомлений через очереди RabbitMQ. Он позволяет создавать уведомления, которые будут автоматически доставлены пользователю через заданное время.

## Особенности
 - Приём запросов на создание отложенных уведомлений
 - Хранение уведомлений в базе данных PostgreSQL
 - Использование RabbitMQ с плагином x-delayed-message для отложенной публикации сообщений
 - Ретрай (повторные попытки) отправки уведомлений при ошибках
 - Кэширование статусов уведомлений в Redis для ускорения доступа
 - Отправка уведомлений через Telegram-бота


## Архитектура
 - API: HTTP интерфейс с ручками для создания, получения и  отмены уведомлений
 - Service: бизнес-логика обработки сообщений, управление retry очередью
 - Repository: слои доступа к PostgreSQL, RabbitMQ, Redis
 - TelegramBot: обёртка для отправки сообщений в Telegram
 - Конфигурация: параметры приложения загружаются из .env файла

## Запуск
 - Создать файл .env по примеру из .env.example
 - В docker-compose запуска сервисов: backend, redis, rabbitmq(PostgreSQL запускается отдельно)
    
        sudo docker-compose up --build -d # запускать в корне проекта
    Миграции в контейнере применяются с помощью скрипта из папки /scripts


## REST API

 - **POST /notify/** — создать новое уведомление
    
    Параметры:
     - **text** — текст уведомления
     - **datetime** — время отправки (RFC3339)
     - **tg_chatid** — Telegram chat ID

 - **GET /notify/{id}** — получить статус уведомления по ID
 - **DELETE /notify/{id}** — отменить уведомление
 - **GET /notifications?page=1&size=10** - получить список уведомлений с пагинацией

## Логирование

Используется zlog с возможностью форматирования времени и выводом JSON-логов
